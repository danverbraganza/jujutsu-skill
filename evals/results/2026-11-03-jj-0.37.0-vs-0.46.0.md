## What differed between the versions

- **Pushing a new bookmark only works out of the box on 0.46.** The skill's push flow, `jj bookmark
  create X` then `jj git push -b X`, failed on 0.37 in every push trial (6 of 6). The error was
  `Refusing to create new remote bookmark X@origin`. Agents recovered with the deprecated
  `--allow-new` or with `jj bookmark track`. jj 0.38 made `jj git push --bookmark` track new bookmarks
  automatically, so on 0.46 the documented flow worked first time in every trial.
- **`jj describe --author` is gone in 0.46.** It was removed in 0.42 in favour of `jj metaedit --author`.
  One 0.46 agent tried it first and recovered.
- **`jj undo <operation>` is gone in 0.46.** An earlier run of this eval, on the skill before
  `b066831`, saw one 0.46 agent pass an operation id to `jj undo`. That is still accepted on 0.37.

## Friction on both versions

None of these come from the version change:

- `discard-awkward-paths`: the first `jj restore` failed in 3 of 3 trials on each version, because
  `docs/notes (draft).md` is a fileset syntax error unless quoted. One 0.46 agent then ran
  `jj restore file:"docs/notes (draft).md" ~scratch.txt`. jj read `~scratch.txt` as "everything except
  scratch.txt" and reverted all the other changes. The agent spotted it with `jj st`, ran `jj undo`,
  and redid the restore with `file:"~scratch.txt"`.
- `revert-commit`: agents reached for `jj backout`, which was removed in 0.35 (3 of 3 trials on each
  version), before finding `jj revert`.
- `squash-into-parent` on 0.37 (1 of 3 trials): `jj squash --from X --into Y` without `-m` opened the
  editor, because both commits have descriptions.
- `edit-earlier-commit` on 0.37 (2 of 3 trials): `jj edit` on the empty working-copy commit, which jj
  had already abandoned when the agent moved away from it.
- One trial each guessed a command or flag that does not exist: `jj files`, `jj cat` (gone before
  0.37), `jj util list-commands`, `jj log --all`, `jj show <rev> -- <path>`, and a malformed `-T`
  template.
- `commit-large-file`: every agent hit `Refused to snapshot some files`, as the scenario intends,
  and committed the file anyway.
